## Writing conventions (verified against `main.tex`)

- **Voice**: multi-author “we”.
- **Product names**: `\multit{}` → `\texttt{ECLARE}`; `\singlet{}` → `KD-CLIP`. Do not invent macros. Dataset macros: `\pinkdata{}` (PFC\_Zhu), `\purpledata{}` (DLPFC\_Ma), `\orangedata{}` (Midbrain\_Adams), `\greendata{}` (DLPFC\_Anderson), `\yellowdata{}`, `\greydata{}`, `\velmeshev{}`, `\wang{}`.
- **CLIP vs KD-CLIP vs ECLARE**: CLIP = single contrastive teacher (no KD). KD-CLIP (`\singlet{}`) = single-teacher distillation. ECLARE (`\multit{}`) = multi-teacher ensemble. Never treat these as interchangeable.
- **Diagonal vs vertical**: unpaired RNA/ATAC from different nuclei = diagonal. Paired multiome / WNN-style methods (MOJITOO) = vertical unless the manuscript explicitly used a GAS workaround. Reviewer R1.2 already flags this.
- **Editing safety**: minimal surgical diffs. Preserve labels, `\ref{}` targets, and useful submitted wording unless the revision evidence supersedes it.
- **Empirical integrity (non-negotiable)**: never invent numbers, p-values, iLISI/ARI/NMI/ASW/FOSCTTM/kBET, sample sizes, `distil_lambda`, teacher counts, or biological interpretations. If output is missing, read the script or ask.
- **Front matter**: do not rewrite authors, ORCID, acknowledgments, funding, or availability unless asked.
- **Hypothesis-generating biology**: keep ABHD17B / GRN / developmental claims aligned with the Results language. Do not upgrade them to validated mechanisms in the Abstract, Discussion, or reviewer response.

## Revision workflow

Copy this checklist and work **one comment ID (or one Theme) at a time**.
If the user says “next” or does not name an ID, take the first still-open
**Tier 1** item in [COMMENT_MAP.md](COMMENT_MAP.md).

```
Revision progress:
- [ ] Identify comment ID(s) and overlapping Theme (A–H)
- [ ] Read tracker subsection + the cited manuscript passage
- [ ] Trace claims to scripts via METHODS_SCRIPT_MAP.md
- [ ] Classify: analysis / wording-only / both / editorial
- [ ] Propose the experiment or prose change; wait if new compute is needed
- [ ] Draft Response + Changes made
- [ ] Apply surgical manuscript/SI edits
- [ ] Update tracker macros + Markdown twin
```

**Step 1 — Identify the real request.** Quote the reviewer’s request list,
not just the concern. Several IDs (R1.3 / R2.4 / R3.2 / R3.4; R1.1 / R1.2;
R1.8 / R2.5 / R3.5) should be answered once via the matching Theme, then
cross-referenced from each ID.

**Step 2 — Locate evidence.** Read the manuscript subsection, then the
implementation anchors in [METHODS_SCRIPT_MAP.md](METHODS_SCRIPT_MAP.md).
Job IDs currently hardcoded in `scripts/plot_figures.py` (`methods_id_dict`)
are the figure-generation provenance for Fig. 2 — do not silently swap them.

**Step 3 — Decide the revision type.**

| Type | Default action |
|---|---|
| Wording / framing (R1.4, R1.m2, R1.m3, R2.3) | Draft manuscript + response text. No new runs. |
| Missing documentation (R1.m4, R3.m1, R3.m2, R1.8) | Document actual behavior from code; do not invent a protocol. |
| New experiment (R1.1–R1.3, R1.5, R1.6, R1.9, R2.1, R2.4, R3.2–R3.4) | Outline design, scripts to reuse, and what would falsify the claim. **Do not launch training jobs unless the user asks.** |
| Editorial (STAR Methods, length, Key Resources) | Check journal instructions; convert Methods without changing scientific content. |

**Step 4 — Draft the point-by-point block.** Response structure:

1. One-sentence restatement of the concern (not defensive).
2. What was done / what the existing evidence already shows, with
   figure/table/script pointers.
3. What changed in the manuscript (section/figure labels).
4. Explicit limitations if the request is only partially met.

**Step 5 — Edit the manuscript.** Prefer tightening SOTA / “best balance”
language over claiming new SOTA after an incomplete benchmark. If the user
chooses the “this is a zero-shot comparison” path for R1.1, temper the
SOTA claim in Abstract, Results (`sec:clip_benchmark`), and Discussion
together.

**Step 6 — Close the tracker item** using the macros above.

## Terminology to keep straight in responses

- **Zero-shot transfer**: teachers trained on paired *source*; student (or
  CLIP) evaluated on held-out *target* without training on that target.
  Native to CLIP/KD-CLIP/ECLARE. Not native to MultiVI, GLUE, scDART, scJoint.
- **`distil_lambda`**: default `0.1` in `src/eclare/run_utils.py`. Weights
  the **KD** term vs the **OT-CLIP** term; reviewers read this as OT-CLIP
  dominating. Confirm the current loss combination in `eclare_pass` /
  `Knowledge_distillation_fn` before explaining λ.
- **Compound metric** (R1.9): `compound_metric()` in `src/eclare/eval_utils.py`
  uses `multimodal_ilisi`, `nmi`, and `ari` — the last two need target
  cell-type labels.
- **kBET “batch”** (R1.m1): current SI caption (`supfig:batch_kbet`) uses
  source–target configuration / source dataset identity, not donor/sequencing
  batch.
